# 工厂食堂报餐系统需求文档

## 1. 项目背景

工厂办公楼与食堂距离较远，员工每日就餐前需前往食堂查看当日菜品，存在以下问题：

1. **信息获取不便**：员工无法提前了解菜谱，需专门跑一趟食堂才能确认当日餐食安排。
2. **备餐缺乏依据**：食堂无法提前掌握实际就餐人数，只能凭经验备餐，容易导致备餐过多或不足。
3. **食材浪费严重**：部分员工临时外出就餐或改变就餐计划，食堂未能及时调整备餐量，造成食材浪费。
4. **员工体验不佳**：员工无法提前规划就餐安排，也难以对菜品表达偏好和反馈建议。

本系统通过微信群分享链接的方式，让员工在手机上提前查看菜谱并报名是否就餐，食堂根据报名人数精准确定备餐量，从而提升就餐体验、减少食材浪费、优化食堂运营效率。

## 2. 核心目标

- 员工无需前往食堂，通过手机即可查看每日菜谱。
- 员工提前报名就餐，食堂按需备餐，减少浪费。
- 员工可查阅历史菜谱，对菜品进行评价，也可提交菜品建议。

## 3. 使用场景

| 场景 | 说明 |
|---|---|
| 游客查看菜谱 | 打开链接即可查看今日往后 2 周（含今日共 15 天）内的菜单，无需登录 |
| 员工报餐 | 登录后选择日期和餐次，点击报名（用餐当日 00:00 前） |
| 员工取消 | 临时有事不去，在用餐当日 00:00 前取消 |
| 食堂发布菜单 | 食堂管理员录入菜单，最多可发布今日往后 2 周（含今日共 15 天）的菜品 |
| 食堂看备餐量 | 每天查看每个餐次的报名人数，按报名人数备餐 |
| 现场核销 | 员工到食堂报工号，工作人员核对后确认已就餐；未报名但到场就餐的登记后计入违约 |
| 管理员工账号 | 食堂管理员批量导入或手动添加员工账号；密码重置与账号禁用由超级管理员负责 |
| 临时取消菜品 | 管理员因食材不足等原因临时下架某个菜品 |
| 菜品点评 | 员工对当餐实际就餐（已核销或未报名就餐）的菜品点赞或踩 |
| 提建议 | 员工提交想吃的菜品建议 |
| 查看历史菜谱 | 按日期查询之前发布过的菜单 |

## 4. 用户角色

| 角色 | 说明 |
|---|---|
| 游客（未登录） | 查看今日往后 2 周（含今日共 15 天）内的菜谱、查看 30 天内的历史菜谱 |
| 普通员工（已登录） | 报餐、取消、取餐核销、点评菜品、提建议、修改密码、查看违约次数 |
| 食堂管理员 | 导入/添加/编辑员工账号、发布菜谱、设置核销规则、查看统计数据、现场核销、查看建议、临时取消菜品 |
| 超级管理员 | 创建食堂管理员账号、查看用餐数据、浪费情况、违约情况，禁用/启用食堂管理员和员工账号，重置食堂管理员和员工密码 |

**账号来源说明**：
- 超级管理员账号由系统数据库初始化时预置（账号 admin，默认密码 admin123，首次登录后强制修改密码，系统中有且仅有一个，不可被禁用）。
- 食堂管理员账号由超级管理员创建，系统可存在多个；创建时填写工号、姓名、部门，默认密码为 123456，首次登录后强制修改密码。
- 员工账号由食堂管理员批量导入或手动添加。

## 5. 功能需求

### 5.0 首页（无需登录）

**菜谱展示（一屏展示）**
- 打开首页直接展示今日往后 2 周（含今日共 15 天）内的菜单，按天分早餐、午餐、晚餐。
- 采用横向滑动或标签页切换日期，早/午/晚餐以标签切换，确保一屏内完整展示，无需下拉滚动。
- 每道菜显示：菜名、口味标签、点赞/点踩数（首页和历史菜谱均显示）。
- 已登录用户的已报名餐次显示"已报名"状态标识（未登录用户不显示该标识）。
- 被管理员临时取消的菜品显示"已下架"标识。
- 无需登录即可查看。

**历史菜谱查询**
- 提供日期选择器，可按日期范围查询之前发布过的菜单，最多可查询当天往前推 30 天内的历史菜单。
- 支持快速查看"上周"菜单。

### 5.1 员工端

**登录**
- 使用工号登录，不需要填写手机号。
- 首次登录：工号 + 默认密码 123456。
- 登录后强制修改密码，之后使用工号和新密码登录。
- 支持"记住登录状态"，下次打开自动登录。
- 账号被禁用后无法登录，需联系超级管理员处理。

**报餐**
- 在首页菜谱上，对想吃的餐次点击"报名"即可，不勾选具体菜品。
- 只要菜谱已发布即可报名，无开始时间限制。
- 报名须在用餐当日 00:00 之前完成，超过用餐当日 00:00 不可报名。
- 报餐成功后显示"已报名"状态。
- 同一餐次可重复修改，以最后一次提交为准；修改在数据上视为一次取消后重新报名。

**取消报餐**
- 取消须在用餐当日 00:00 之前完成（即最晚前一日 23:59:59）。
- 超过用餐当日 00:00 后不可取消。

**取餐核销**
- 员工到食堂后，向工作人员报工号。
- 工作人员在系统中输入工号，查询该员工当餐报餐记录，确认后点击核销。

**用餐记录**
- 查看自己历史报餐和就餐记录。
- 查看违约次数（违约包括两类：核销截止时间过后仍未核销的报餐记录；未报名但到现场就餐的记录）。

**菜品点评**
- 对当餐实际就餐（已核销或已登记未报名就餐）的菜品可以点赞或踩。
- 已下架的菜品不允许点评。
- 点评仅当日有效，超过当日 23:59:59 后不可点评。
- 每道菜显示赞和踩的数量，同名菜品按菜名合并统计。

**提建议**
- 员工可以提交想吃的菜品建议，填写建议内容后提交。
- 可查看自己提交过的建议及状态。

**修改密码**
- 所有登录账号（普通员工、食堂管理员、超级管理员）均可在个人中心修改自己的登录密码。

### 5.2 食堂管理员端

**管理员工信息**
- 支持通过 Excel/CSV 文件批量导入员工信息。
- 支持在页面上手动添加单个员工，填写：工号、姓名、部门。
- 导入或添加后系统自动生成账号，工号为登录名，默认密码为 123456。
- 支持查看和编辑已添加的员工列表（工号不可修改，可修改姓名、部门）。
- 员工密码重置与账号禁用由超级管理员负责，食堂管理员不可重置员工密码、不可禁用员工账号。

**发布菜谱**
- 可发布今日往后最多 2 周（含今日共 15 天）内的菜单，每天分早/午/晚餐。
- 支持添加菜品名称、口味标签。
- 支持复制上周菜单，快速修改后发布。
- 菜谱发布后即可报名。
- 已发布菜谱不可编辑，如需调整只能对菜品执行下架/恢复。
- 系统不存储菜谱草稿，菜谱数据仅在发布后保存。

**临时取消菜品**
- 管理员可在已发布的菜单中，临时下架某个菜品（如因食材不足、厨师临时调整等原因）。
- 被下架的菜品在员工端显示"已下架"标识。
- 报餐按餐次进行、不针对具体菜品，因此菜品下架不影响该餐次的报名与核销；已报名该餐次的员工不受影响，仍可正常就餐。
- 支持恢复已下架的菜品。

**设置核销规则**
- 设置每餐的核销截止时间（默认值 = 当餐结束时间：早餐 09:00、午餐 13:30、晚餐 19:00，管理员可覆盖），超过核销截止时间未核销的报餐记录记为违约。

**查看统计**
- 按日期、餐次查看报餐人数（报餐以餐次为单位，不提供按菜品的报名统计）。
- 按部门查看报餐人数分布。
- 查看每日实际就餐人数（核销数 + 未报名就餐数）与报餐人数的差异。

**现场核销**
- 输入员工工号，查询该员工当餐报餐记录。
- 确认员工到场后，点击核销。
- 员工未报名但到现场就餐的，工作人员登记"未报名就餐"记录，该记录计入违约。
- 核销与未报名登记互斥：工号查询有报餐记录时走核销，无报餐记录时走未报名登记，同一员工同一餐次只产生一条就餐记录。
- 未报名就餐登记默认在当餐时段内进行，系统不额外限制登记时点。

**查看建议**
- 查看员工提交的菜品建议列表。
- 可标记建议的处理状态（待处理/已采纳/已拒绝）。

### 5.3 超级管理员端

**账号管理**
- 创建食堂管理员账号：填写工号、姓名、部门，默认密码为 123456，首次登录后强制修改密码（系统可存在多个食堂管理员）。
- 禁用/启用食堂管理员账号和员工账号。
- 重置食堂管理员和员工的登录密码，重置后统一为 123456。

**违约查看**
- 查看违约员工名单及各员工的违约次数。

**数据看板**
- 每日就餐人数趋势。
- 各菜品受欢迎程度排行（含点赞/点踩数，同名菜品按菜名合并统计）。
- 报餐未到率（浪费率）。
- 各部门就餐情况对比。

## 6. 业务规则

| 规则 | 说明 |
|---|---|
| 报名与取消 | 用餐当日 00:00 前可报名、修改、取消；超过用餐当日 00:00 后不可报名、修改或取消 |
| 报名条件 | 菜谱已发布即可报名，无开始时间限制 |
| 发布范围 | 食堂管理员最多发布今日往后 2 周（含今日共 15 天）内的菜品 |
| 菜谱查看范围 | 员工和游客可查看今日往后 2 周（含今日共 15 天）内的菜谱（与发布范围一致）；历史菜谱最多可查看当天往前推 30 天 |
| 菜谱不可编辑 | 菜谱发布后不可编辑，如需调整只能对菜品执行下架/恢复 |
| 默认不报餐 | 员工不主动报名，视为该餐不吃 |
| 违约记录 | 核销截止时间过后仍未核销的报餐记录记为违约；未报名但到现场就餐的也记为违约；员工可查看自己的违约次数，超级管理员可查看违约员工名单及违约次数 |
| 核销方式 | 员工报工号，管理员查询并核销；核销截止时间默认为当餐结束时间（早餐 09:00、午餐 13:30、晚餐 19:00），管理员可在核销规则中覆盖调整 |
| 默认密码 | 新添加员工默认密码为 123456；超级管理员预置账号为 admin/admin123（系统唯一）；食堂管理员账号由超级管理员创建，默认密码 123456；所有账号首次登录后均强制修改密码 |
| 点评权限 | 当餐已核销或已登记未报名就餐的员工，才能对当餐菜品进行点赞或踩；已下架菜品不允许点评；点评仅当日有效，超过当日 23:59:59 后不可点评 |
| 手机号保护 | 系统中不展示员工手机号，登录和核销均使用工号 |
| 账号禁用 | 超级管理员可禁用/启用食堂管理员账号和员工账号；食堂管理员不可禁用员工账号；被禁用账号无法登录；超级管理员账号不可被禁用 |
| 密码重置 | 超级管理员可重置食堂管理员及员工的密码，重置后统一为 123456，下次登录时强制修改 |
| 菜品下架 | 管理员可临时下架已发布的菜品，报餐按餐次进行，已报名员工不受影响 |
| 管理员账号 | 超级管理员账号由数据库初始化预置（admin/admin123，系统中有且仅有一个，不可被禁用）；食堂管理员账号由超级管理员创建，系统可存在多个 |

## 7. 数据需求

**员工信息**
- 工号、姓名、部门、密码、账号状态（正常/禁用）、角色（普通员工/食堂管理员/超级管理员）、是否已修改初始密码。

**菜谱信息**
- 日期、餐次（早/午/晚）、菜品名称、口味标签、菜品状态（正常/已下架）。

**核销规则**
- 餐次（早/午/晚）、核销截止时间（未配置时使用默认值：早餐 09:00、午餐 13:30、晚餐 19:00）。

**报餐记录**
- 员工、日期、餐次、报餐状态（已报名/已取消/已核销/违约）、报餐时间、取消时间（修改视为一次取消后重新报名，以最后一次记录为准）。

**核销记录**
- 报餐记录、核销时间、核销人（管理员）。

**未报名就餐记录**
- 员工、日期、餐次、登记时间、登记人（管理员）。

**菜品点评**
- 菜品、员工、所属餐次（用于校验该员工当餐已核销或已登记未报名就餐）、评价类型（赞/踩）、评价时间。

**建议信息**
- 员工、建议内容、提交时间、处理状态。

## 8. 使用方式

- 员工无需安装任何 App。
- 食堂管理员在微信群里分享系统链接。
- 员工点击链接，用手机浏览器打开即可看到今日往后 2 周（含今日共 15 天）内的菜单。
- 想报餐或点评时再登录，登录用工号和密码。
- 首次登录用工号和默认密码 123456，登录后强制修改密码。
