## 二、使用手册

### 2.1 员工端（手机 H5）

访问系统首页即可使用（无需安装 App）。

**看菜谱（无需登录）**
- 首页默认展示今天起 15 天内的菜单，顶部日期横滑切换，早/午/晚标签切换。
- 每道菜显示口味标签和点赞/点踩数。

**报餐与取消**
- 登录后，在想吃的那天点餐次下方的 **报名** 按钮（例如明天中午的饭）。
- ⏰ **关键规则**：报名/修改/取消必须在**用餐当天 00:00 之前**完成。例如想吃 11 月 2 日午餐，最晚 11 月 1 日 23:59:59 报名。当天临时想吃的，只能到现场走"未报名就餐"登记，并计入违约。
- 报名后可随时（同规则内）取消再重新报名，以最后一次为准。

**点评菜品**
- 只对"当天已核销"（现场确认吃过）的菜品开放点赞/点踩，仅当天有效。

**提建议**
- 底部 Tab「我的」→「我的建议」→ 填写内容提交（最多 200 字）。
- 食堂管理员会标记"待处理 / 已采纳 / 已拒绝"，可在同一页查看处理结果。

**用餐记录与违约**
- 底部 Tab「记录」：查看每次报餐/核销/取消明细，顶部卡片显示违约次数。
- 违约 = 报名了没去核销，或没报名但去现场吃了。请合理规划报餐。

**账号**
- 首次登录使用管理员分配的工号 + 默认密码 123456，**登录后强制修改密码**。
- 勾选"记住登录状态"后 30 天内免登录。

### 2.2 管理端（食堂管理员 & 超级管理员）

访问 `/admin/` 路径登录（PC 浏览器体验最佳，手机也可用）。登录后默认进入**首页仪表盘**：今日报名/核销、本月违约、菜品满意度、近 7 天报名 vs 实际就餐柱状图、每日就餐率进度条、最新建议动态。

**现场核销（食堂管理员）**
- 输入员工工号 → 查询 → 显示该员工当餐状态：
  - 已报名 → 点【确认核销】
  - 未报名 → 点【登记未报名就餐】（计违约）
  - 已过核销截止 → 提示该餐已判违约，不可补核销
- 登录后直接落在核销页，工号输入框自动聚焦，现场操作快。

**菜谱发布与下架（食堂管理员）**
- 「菜谱发布」：选日期和餐次 → 逐行添加菜名与口味标签 → 发布。支持一键**复制上周菜单**。
- 「菜品下架」：食材不足等临时情况，把某道菜切换为"已下架"（员工端置灰显示），随时可恢复。报餐按餐次进行，下架菜品不影响已报名员工。

**核销规则（食堂管理员）**
- 三餐核销截止时间默认 早餐 09:00 / 午餐 13:30 / 晚餐 19:00，可覆盖。超过截止未核销的报名自动判违约。建议仅在餐次开始前调整。

**数据统计（食堂管理员）**
- 按餐次报名人数、按部门分布、近 30 天实际就餐 vs 报名差异。
- **用餐明细**（重点）：选某一天，逐人分页查看当天三餐状态——谁报名且来了、谁报名没来、谁没报名但来了、谁没报名也没来；支持部门/工号筛选与 **CSV 导出**（Excel 可直接打开）。

**建议管理（食堂管理员）**
- 查看员工建议列表，标记处理状态（待处理/已采纳/已拒绝）。

**账号管理 / 员工管理 / 违约查看 / 数据看板（超级管理员专属）**
- **账号管理**：创建食堂管理员账号（默认密码 123456）、禁用/启用账号、重置密码（重置后为 123456 并强制改密）。
- **员工管理**：手动添加员工、CSV 批量导入（模板：`工号,姓名,部门`，UTF-8 编码）、编辑姓名/部门（工号不可改）。
- **违约查看**：违约人员名单与次数汇总。
- **数据看板**：就餐趋势折线、菜品赞踩排行、报餐未到率（浪费率）、各部门就餐对比。

### 2.3 角色与登录速查

## 三、部署指南（Render + Supabase）

### 3.1 成本：近乎零成本

| 资源 | 方案 | 费用 |
|---|---|---|
| 后端 + 前端托管 | Render Web Service（Free 档，Docker 部署，自动 HTTPS） | **免费** |
| 数据库 | Supabase PostgreSQL（Free 档，500MB 存储） | **免费** |
| 域名（可选） | `.cn` 域名（阿里云/腾讯云首年约 **35 元/年**） | 35 元/年 |
| 其余全部 | 构建流水线、HTTPS 证书、CDN、迁移工具 | **免费** |

> 域名非必需：Render 会分配 `xxx.onrender.com` 免费域名 + 自动 HTTPS，直接可用。绑定自己的 `.cn` 域名仅是为了好记。

**免费档的边界（了解即可）**：
- Render Free：15 分钟无流量自动休眠，首次访问冷启动 10~30 秒；每月 750 小时实例时长（单服务跑满一个月刚好用完）。
- Supabase Free：500MB 存储、2 个项目；**一周无 API 请求项目会暂停**（有人正常使用就不会触发）。
- 规模评估：数百名员工 × 每天 3 餐的报餐数据一年不到 100 万行，500MB 绰绰有余——适合工厂/学校/小团队场景的学习与轻量使用。

### 3.2 部署架构

```
微信/浏览器
   │  https://你的域名 或 xxx.onrender.com
   ▼
Render Web Service (Frankfurt, Free)
   ├─ Go 单二进制：API + 员工端H5 + 管理端（前端构建产物嵌入二进制）
   └─ 启动时 AUTO_MIGRATE=1 自动执行数据库迁移（幂等，无需手动建表）
        │  Session Pooler (IPv4, TLS)
        ▼
Supabase PostgreSQL (eu-west-1 爱尔兰, Free)
```

**为什么这样部署**：单服务单进程，无 CORS 问题；Render Frankfurt 与 Supabase 爱尔兰机房就近，单次 DB 往返约 20ms；数据库只走 Session Pooler（IPv4），规避 Render 容器无 IPv6 的限制。

### 3.3 部署步骤

**第 1 步：创建 Supabase 项目**
1. [supabase.com](https://supabase.com) 注册并 New Project（区域选 **West EU (London)** 或 Frankfurt 均可，Free 档）。
2. 记下数据库密码（只显示一次）。
3. 顶部 **Connect** → 连接方式选 **Session pooler** → 复制连接串，形如：
   ```
   postgresql://postgres.<项目ref>:<密码>@aws-0-eu-west-1.pooler.supabase.com:5432/postgres?sslmode=require
   ```
   ⚠️ 不要用 "Direct connection"（`db.xxx.supabase.co`），它是 IPv6-only，Render 容器连不上。

**第 2 步：代码推送到 GitHub**
- 仓库中不含任何真实凭据（连接串只存在于 Render 环境变量和本地 `scripts/local.env`，均已排除出 git）。

**第 3 步：Render 创建 Web Service**
1. [render.com](https://render.com) 用 GitHub 登录 → New → Web Service → 选择仓库。
2. 表单选择：

| 选项 | 值 |
|---|---|
| Language | Docker |
| Branch | main |
| Region | **Frankfurt**（与 Supabase 就近） |
| Instance Type | Free |

3. 展开 **Advanced → Add Environment Variable**，添加：

| Key | Value |
|---|---|
| `DATABASE_URL` | 第 1 步复制的 Session Pooler 连接串 |
| `JWT_SECRET` | 任意 32 位以上随机字符串（自己编） |
| `AUTO_MIGRATE` | `1`（启动时自动建表，幂等） |
| `TZ` | `Asia/Shanghai`（报餐 00:00 截止等规则按北京时间） |
| `DEMO_MODE` | `1`（演示模式，默认开启）或 `0`（关闭） |

**演示模式（DEMO_MODE）说明**：
- 默认开启。开启时：超管 `admin` 密码自动重置为 `123123` 且**不能在系统中修改**（改密接口被拦截，管理端"修改密码"菜单对超管隐藏）——方便把账号公开给他人体验而不担心密码被改。
- 关闭（`DEMO_MODE=0`）后：admin 密码恢复你最后一次设置的值，可正常修改密码。
- 其余角色（食堂管理员/员工）不受演示模式影响。

4. **Deploy Web Service** → 等待构建（首次约 5~10 分钟）。
5. 日志出现 `migrations applied` 和 `server listening` 即成功。

**第 4 步：初始化账号**
- 访问分配的域名 `https://xxx.onrender.com/admin/` → 用种子超管 `admin` / `admin123` 登录（**立即强制改密**）。
- 「账号管理」创建食堂管理员 → 「员工管理」导入员工（或手动添加）→ 把系统链接发到工作群即可使用。

### 3.4 （可选）绑定 .cn 域名

1. 阿里云/腾讯云注册 `.cn` 域名（首年约 35 元，需实名认证）。
2. 域名控制台添加解析记录：类型 `CNAME`，主机记录 `canteen`（或其它前缀），记录值填 Render 分配的域名 `xxx.onrender.com`。
3. Render → 你的服务 → **Settings → Custom Domains → Add Custom Domain** → 填入 `canteen.你的域名.cn` → 按提示验证，Render 自动签发 HTTPS 证书。
4. DNS 生效后（几分钟到几小时），即可用新域名访问。
5. 说明：域名解析到境外托管（Render）不涉及 ICP 备案流程，但境内访问速度与可达性不做保证；如对合规有要求请自行评估。

## 四、本地开发

```powershell
# 前置：Go 1.25+、Node 20+、pnpm 9+
# 1. 配置本地连接串：复制 scripts\local.env.example 为 scripts\local.env 并填入 DATABASE_URL

pnpm admin   # http://localhost:5174

# 改了前端代码后重建产物：
scripts\rebuild-frontend.cmd

# 测试：
cd server && go test ./...
```

## 五、常见问题

| 问题 | 处理 |
|---|---|
| 线上首次打开很慢 | Render Free 休眠机制，冷启动 10~30 秒，属预期；可升级付费档消除 |
| Supabase 项目暂停 | Free 档一周无请求会暂停，去 Supabase 控制台点 Restore 即可 |
| 忘记 admin 密码 | 演示模式（默认）下密码固定为 `123123`；若 `DEMO_MODE=0` 且密码丢失，有数据库访问权限时执行：`cd server && set DATABASE_URL=... && go run ./cmd/smoke/resetpwd admin admin123` |
| 登录提示"请先登录"但刚登录过 | 浏览器缓存旧资源，Ctrl+F5 强刷；或清除该站点缓存 |
| 报餐按钮显示"已锁定" | 已过当天 00:00 截止，只能现场走未报名就餐流程 |
| 员工密码忘了 | 超管在「账号管理」重置，重置后为 123456 且强制改密 |
